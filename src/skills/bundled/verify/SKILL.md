# 验证

当任务需要实际运行更改才能完成时，请使用此技能。

## 目标

生成基于执行而非推断的简短验证结果。优先使用最窄范围的检查来证明更改的行为正常工作。

## 工作流程

1. 识别更改的表面区域。
2. 选择最小的可行验证路径。
3. 运行相关命令或请求流程。
4. 捕获可观察结果：退出状态、关键输出、HTTP状态或更改的行为。
5. 报告通过的内容、未验证的内容以及任何剩余风险。

## 规则

- 不运行任何东西就不要声称成功。
- 优先使用专注的检查而非广泛的冒烟测试。
- 如果仓库没有正式的测试目标，请使用最近的可运行工作流。
- 如果检查因环境限制而被阻止，请明确说明。
- 当有助于重复验证时，包含确切的命令。

## 验证模式

### CLI更改

- 运行受编辑影响的确切命令路径。
- 检查帮助文本、标志、输出格式、退出代码和副作用。
- 对于交互式流程，优先使用最可脚本化的子命令。

参见 `examples/cli.md`。

### 服务器更改

- 仅启动所需的服务。
- 测试更改的路由、处理器或后台路径。
- 验证状态码、响应形状、日志和故障处理。

参见 `examples/server.md`。

## 报告格式

- `已验证:` 你运行的内容和通过的内容。
- `未验证:` 任何你无法运行的内容。
- `风险:` 主要的剩余不确定性（如有）。
